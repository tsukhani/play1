h1. Setting up a captcha

p(note). **Removed in Play 1.13.** Play no longer bundles a captcha generator. The @play.libs.Images.captcha()@ helper and its @jj-simplecaptcha@ dependency were removed (PF-148) so that no downstream distribution carries a loosely-licensed jar. The original tutorial has been replaced with guidance on wiring your own captcha.

h2. <a>Use an external captcha service</a>

For a modern blog engine, delegate spam protection to a dedicated captcha service rather than generating images in-process. Popular options expose a small JavaScript widget plus a server-side verification endpoint:

* "Google reCAPTCHA":https://developers.google.com/recaptcha
* "hCaptcha":https://www.hcaptcha.com/
* "Cloudflare Turnstile":https://www.cloudflare.com/products/turnstile/

The integration shape is the same in each case: drop the widget @<script>@ and a placeholder @<div>@ into your comment form, then in @postComment@ POST the token the widget produces to the provider's verify URL (using @play.libs.WS@) and reject the submission unless the response is successful.

h2. <a>The stateless validation pattern still applies</a>

If you generate your own challenge instead, keep it stateless: store the expected answer in the Play **Cache** under a random ID, render that ID as a hidden form field, and compare on submit — exactly as a stateless framework should. For example:

bc. String randomID = Codec.UUID();
Cache.set(randomID, expectedAnswer, "10mn");
// ... render randomID as a hidden field, then on submit:
validation.equals(code, Cache.get(randomID)).message("Invalid code. Please type it again");
Cache.delete(randomID);
