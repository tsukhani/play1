h1. 依存性管理

Play 1.13 のアプリケーションは、依存性解決に "Gradle":https://gradle.org/ を使用します。各アプリケーションのルートに @build.gradle.kts@ があり、Java/Kotlin の依存ライブラリ、リポジトリ、Play モジュールを宣言します。

h2. <a name="declaring">アプリケーションの依存性を宣言する</a>

@build.gradle.kts@ の @dependencies@ ブロックに依存ライブラリを追加します:

bc. dependencies {
    implementation("org.apache.commons:commons-lang3:3.14.0")
    implementation("com.google.guava:guava:33.0.0-jre")
}

リポジトリはファイルの先頭で一度だけ宣言します:

bc. repositories {
    mavenCentral()
}


h2. <a name="modules">Play モジュールをロードする</a>

Play の組み込みモジュール (@crud@、@secure@、@testrunner@、@docviewer@) は Maven 座標としてではなく、Play 1 プラグインの DSL で宣言します:

bc. plugins {
    id("org.playframework.play1")
}

play1 {
    modules("crud", "secure")
}

プラグインは、宣言された各モジュールをビルド時にアプリケーションの @modules/@ ディレクトリに展開します。モジュールオーバーレイ (レガシーの @override(f, t)@ 機構) は、モジュールがディスク上の実ディレクトリであるため透過的に動作します。


h2. <a name="resolving">依存性の解決</a>

Gradle は、最初の @play@ コマンド (@play run@、@play test@ など) 実行時に依存性を解決し、@build.gradle.kts@ が変更されるたびに再解決します。解決後のクラスパスを確認するには:

bc. play classpath

解決された依存性をツリー形式で表示するには:

bc. ./gradlew dependencies

@build.gradle.kts@ を編集した後で再解決を強制するには:

bc. ./gradlew --refresh-dependencies <task>


h2. <a name="framework">フレームワーク自身の依存性</a>

フレームワーク自身のビルド (@framework/@ 配下) は引き続き Apache Ivy と @framework/dependencies.yml@ の宣言的なマニフェストを使用します。これは内部的なものです。Play 1 フォークのメンテナーが @ant resolve@ を実行して @framework/lib/@ を更新します。アプリケーション開発者がこのファイルに触れる必要はありません。
