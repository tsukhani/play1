h1. キャプチャの設定

p(note). **Play 1.13 で削除されました。** Play はキャプチャ生成機能を同梱しなくなりました。@play.libs.Images.captcha()@ ヘルパーとその @jj-simplecaptcha@ 依存は、配布物にライセンスの曖昧な jar を含めないために削除されました (PF-148)。以前のチュートリアルは、独自のキャプチャを組み込むためのガイダンスに置き換えられています。

h2. <a>外部のキャプチャサービスを使う</a>

最近のブログエンジンでは、画像をプロセス内で生成するのではなく、専用のキャプチャサービスにスパム対策を委譲します。代表的な選択肢は、小さな JavaScript ウィジェットとサーバ側の検証エンドポイントを提供します:

* "Google reCAPTCHA":https://developers.google.com/recaptcha
* "hCaptcha":https://www.hcaptcha.com/
* "Cloudflare Turnstile":https://www.cloudflare.com/products/turnstile/

統合の流れはどれも同じです。ウィジェットの @<script>@ とプレースホルダの @<div>@ をコメントフォームに追加し、@postComment@ でウィジェットが生成したトークンを (@play.libs.WS@ を使って) プロバイダの検証 URL に POST し、成功レスポンスでなければ送信を拒否します。

h2. <a>ステートレスな検証パターンは引き続き有効</a>

独自のチャレンジを生成する場合も、ステートレスに保ちましょう。想定する答えをランダムな ID をキーに Play の **Cache** に保存し、その ID をフォームの隠しフィールドとして描画し、送信時に比較します。ステートレスなフレームワークにふさわしいやり方です。例:

bc. String randomID = Codec.UUID();
Cache.set(randomID, expectedAnswer, "10mn");
// ... randomID を隠しフィールドとして描画し、送信時に:
validation.equals(code, Cache.get(randomID)).message("Invalid code. Please type it again");
Cache.delete(randomID);
